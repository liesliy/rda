# pii_scan

> **Layer**: Layer 4 - Security & Privacy (WARNING-level by default)
> **Status**: 自研实现（无第三方代码，仅调用 opencv 的可选运行时依赖） · RDA v0.9.22 provenance 记录

# 算法说明 — pii_scan

扫描一个 episode 中的三类**客观可复现的隐私暴露证据**。设计前提：宁可漏报、
不可把假证据当真；宁可大声说"没扫到"，不可冒充"扫过且干净"。

## 1. 文本面 — 直接标识符

扫描面 = episode meta 递归展开的所有字符串（深度上限 4、列表上限 50 项）、
task 文本、以及 observation / action 的**特征名**（特征名随数据分发，
常常内嵌采集者或项目名）。每个面按 10 万字符预算截断。

| 检测器 | 结构（正则） | 语义校验器 |
|---|---|---|
| `cn_resident_id` | `(?<!\d)[1-9]\d{5}(?:19|20)\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01])\d{3}[\dXx](?!\d)` | GB 11643-1999 mod-11-2 校验位复核 |
| `cn_mobile` | `(?<!\d)1[3-9]\d{9}(?!\d)` | 长度 11 且第二位落在 3–9 |
| `email` | `[A-Za-z0-9._%+-]+@[A-Za-z0-9-]+(?:\.[A-Za-z0-9-]+)*\.[A-Za-z]{2,}` | 恒真（结构即语义） |
| `mac_address` | `(?<![0-9A-Fa-f:])(?:[0-9A-Fa-f]{2}:){5}[0-9A-Fa-f]{2}(?![0-9A-Fa-f:])` | 恒真 |
| `ipv4` | `(?<!\d)(?:\d{1,3}\.){3}\d{1,3}(?!\d)` | 公有/私有分类；仅公有地址记为暴露 |

**为什么要有"语义校验器"这一层**：正则只证明"长得像"。18 位数字里只有带正确
校验位的那一小部分才是身份证号； dotted-quad 里只有可路由地址才构成地理暴露。
没有这一层，任何时间戳数字串都会被当成身份证，运维三天后就学会无视整个指标。

已知残留误报：形如 `1.2.3.4` 的软件版本号会被 ipv4 检测器以 medium 置信度
记为"公网地址"。这是"宁可漏报"原则的反向代价——同时它也会被报告侧脱敏替换，
因此不构成泄漏。

## 2. 数值特征 — 精确地理坐标

lat / lon 类特征**成对出现**（缺一不构成定位）且 ≥95% 采样落在合法值域时，
记为 `geolocation_pair`。列名识别采用**分隔符整词匹配**（`re.split(r"[^a-z0-9]+")`）：
`gps_lat`、`robot.lon` 能被识别，而 `translation` / `plate` / `relation` /
`isolation`（内部均含子串 "lat"）不会被误伤。

## 3. 视频帧 — 人脸

`--pii-video` 时对每个相机均匀采样 N 帧（默认 5），解码为 BGR 后跑
Haar 级联 `haarcascade_frontalface_default.xml`，≥2 帧命中才报 face finding
（单帧命中更可能是纹理巧合）。可选依赖 `opencv-python-headless>=4.8,<5`：
上界有实测依据——4.14.0 自带 19 个级联 XML，5.0.0 一个都不带。

## 输出与判定语义

- Details 中每个 finding 只有**掩码片段**（`138****5678` 形态）+ raw 值的
  SHA-256 前 12 位指纹（用于跨 episode 去重），**原文永不写入** `measurement`
  / `details` / `message`。
- 报告层复用同一张检测器表（`redact_text()`）对所有回显的自由文本做替换，
  因此"报告隐藏了什么"与"报告报了什么"不可能分歧。
- **默认 WARNING 级**：`has_finding=True` 但 `assessment.status="pass"`，
  判定不变。`--pii-strict` 才把本指标提升为当次运行的 CRITICAL 闸门。
- **优雅降级**：任何检测器无法运行时写入 `details["not_scanned"]` 并体现在
  message 里，绝不静默降级为"扫过且干净"。
